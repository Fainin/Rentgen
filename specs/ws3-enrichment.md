# Feature: Workstream 3 — Live price research & population (`enrichment/`)

> Generated by `/upfront:feature` on 2026-07-18. No spike — direction validated by the
> team design spec (`docs/specs/2026-07-18-rentgen-sdk-design.md`) and workstream spec
> (`docs/specs/workstreams/3-live-research-and-population.md`).

## Intent

**Problem:** A classified `DetectedObject` is worthless on screen without a *defensible*
price. This module turns one object into grounded resale + rent/day ranges backed by real
web sources, so the "idle capital" total is believable, not hallucinated.

**Success metric:** `createEnrichmentAdapter({ tavilyApiKey, openaiApiKey })` prices a real
venue object with plausible EUR ranges and ≥1 clickable, real source link, in < ~8s.
The stub prices anything instantly offline.

**Scope:** Everything inside `packages/sdk/src/enrichment/` only — three files
(`tavily-comps.ts`, `stub.ts`, `index.ts`). Imports from outside the folder = frozen
types/interfaces only.

**Must NOT happen:**
- Editing frozen contracts (`types.ts`, `adapters/types.ts`, `events.ts`) or other
  streams' files.
- Invented/hallucinated source URLs — every `Source.url` comes from a Tavily result.
- Reading `import.meta.env` — keys arrive via factory config only.
- Silently swallowing API failures — hard failure throws; Stream 4 surfaces `scan:error`.
- Mixed currencies — all output uses config currency (default `'EUR'`).

N/A — no spike. Pre-validated by team decisions: adapter pattern, Tavily→OpenAI pipeline,

## What the spike skipped

### Error cases
- **Tavily returns zero useful results** for both queries → nothing to ground on → throw
  (a wrong-but-confident price is worse than an error card).
- **Rental comps missing but resale comps exist** (common — most objects have resale
  listings, few have rental listings) → derive `rentPerDay` from resale midpoint heuristic
  (~1.5–3%/day), reuse the resale sources. Marked `ponytail:` in code.
- **OpenAI returns malformed / non-JSON** → defensive parse, retry once with a "JSON only"
  nudge, then throw.
- **Degenerate numbers** (min > max, ≤ 0, absurd outliers) → swap/clamp after parse;
  throw if still unusable.
- **Tavily browser CORS blocked (hour-1 risk, design §9)** → transport swap confined to
  `tavily-comps.ts` (e.g. proxy URL passed via config or hosted relay). Interface hides it.
- **Network/HTTP errors, rate limits** → throw with a message naming the failing service.
  Per-item failure isolation is Stream 4's concern (parallel enrich).

### Concurrency
Not applicable — adapter is stateless; each `enrich()` call is independent. Stream 4 may
call it in parallel per item; no shared mutable state exists here.

### Hidden complexity
- **Grounding is the product.** The temptation is to let OpenAI price from priors and
  decorate with links. The pipeline must be: Tavily results in → OpenAI reconciles *only
  those* → sources are the actual result URLs. Prompt must forbid outside knowledge for
  the numbers.
- **Comp noise:** search results mix new-price, broken-item, wrong-model listings. The
  reconcile prompt asks for a *range* (min/max of plausible used comps), not a point —
  ranges absorb noise.
- **Query construction matters more than the model:** `"{name} {condition}" used price site:ebay OR marketplace`
  style queries beat generic ones. Keep query builders as small pure functions (testable
  by eye).
- **API keys in browser bundle** — accepted demo-scoped risk (CLAUDE.md); rotate after.

## Requirements

- **R1:** `enrichment/index.ts` exports `createEnrichmentAdapter(config: { tavilyApiKey?: string; openaiApiKey?: string; currency?: string }): EnrichmentAdapter` — returns the real adapter iff both keys are present, else the stub.
- **R2:** Stub: deterministic (same input → same output), zero network, resolves fast (<50ms), returns valid `EnrichedItem` with ≥1 plausible fake source; prices vary by category so the demo total looks real.
- **R3:** Both adapters return an `EnrichedItem` that preserves *every* incoming `DetectedObject` field unchanged (esp. `id`) and adds `resale`, `rentPerDay`, `sources`. New object — no mutation of the input.
- **R4:** Real adapter: every `Source.url` is a URL present in Tavily's results; `sources.length ≥ 1` or the call throws.
- **R5:** All `PriceRange`s satisfy `0 < min ≤ max` and `currency === config.currency ?? 'EUR'`.
- **R6:** Real adapter: two Tavily searches per object (resale comps, rental comps) run in parallel; one OpenAI JSON-mode call reconciles both ranges.
- **R7:** Malformed OpenAI JSON → one retry, then throw. Any hard API failure (4xx/5xx/network) → throw with service-naming message. Never resolve with fabricated data.
- **R8:** If rental comps are empty, `rentPerDay` = heuristic from resale midpoint (1.5–3%/day band), sources reused from resale. If both comp sets empty → throw.
- **R9:** No imports from outside `enrichment/` except `../types.js` and `../adapters/types.js`. No `import.meta.env`.
- **R10:** Hour-1 smoke check: a browser `fetch` to Tavily from the dev shell either works or the CORS fallback transport is wired — before any polish work.

## Architecture

**Where code lives:** `packages/sdk/src/enrichment/`
- `index.ts` — factory + barrel (R1). ~30 lines.
- `stub.ts` — offline adapter (R2). Category→price table, hash of `name` for deterministic jitter.
- `tavily-comps.ts` — real adapter (R4–R8): query builders → 2× Tavily `fetch` → OpenAI reconcile → validate/clamp → `EnrichedItem`.

**Data models:** frozen `DetectedObject → EnrichedItem` (`PriceRange`, `Source`) — no new types. Internal-only shapes (Tavily response, reconcile payload) stay private to `tavily-comps.ts`.

**Integration points:** Stream 4 imports `createEnrichmentAdapter` from the folder barrel and wires it in `RentgenClient`/`configureRentgen`. Nothing else touches us.

**Spike code to replace:** none.

### Growth points
- **New comp source** (eBay API, local classifieds): new file implementing `EnrichmentAdapter`, one line in the factory. The seam already exists — don't pre-build a source registry.
- **CORS transport swap:** isolated behind a small `search()` function inside `tavily-comps.ts`; only that function changes.
- **Per-item currency / price confidence / availability:** needs new fields on frozen `EnrichedItem` → **team decision with Streams 4 & 5** — do not add unilaterally.
- **Server-side move (post-hackathon):** the adapter body relocates behind a thin endpoint; factory + interface unchanged.

### Structural issues
Area is clean — empty folder, greenfield inside a locked seam.

## Thinking Record

**Validated by team spec:** pipeline shape (Tavily→OpenAI), factory seam, frozen output type, EUR default, stub-first rule, CORS risk plan.
**Surfaced during solidification:** rental-comps scarcity → resale-derived heuristic; zero-grounding → throw, not guess; range-not-point pricing to absorb comp noise; grounding-prompt discipline (numbers only from provided results).
**Key decisions:** throw on ungroundable items (stub keeps demo alive); single JSON-mode reconcile call for both ranges (1 call = cheaper, atomic); 2 parallel Tavily queries per object; gpt-4o-mini class model for reconcile.
**Risks accepted:** browser-exposed keys (demo-scoped, rotate after); no automated tests (hackathon cut — smoke on real objects); rent heuristic is a guess band, defensible enough for a demo.
